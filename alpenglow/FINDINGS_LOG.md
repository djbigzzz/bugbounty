## ⭐ CRYPTO DETERMINATION — identity-cancellation attack (the audit's #1 lead) — RESOLVED NON-EXPLOITABLE
Verified three independent ways (consensus-pool agent from builder side, cert-verify agent from verifier side, + main-thread read of `solana-bls-signatures 3.4.0` source):
1. **Library guards base3.** `verify_distinct_aggregated_pre_hashed` rejects any input pubkey and any message-grouped pubkey with `is_identity()` → a fully-cancelling partition (`agg_fallback = identity`) returns `VerificationFailed`. (Source: `signature/verify_distinct.rs`, the `if bool::from(pubkey.is_identity()) { return Err(VerificationFailed) }` checks.)
2. **PoP binding caps partial cancellation.** To cancel, the attacker needs the subset's secret keys to sum to zero ⇒ can only cancel keys it fully controls ⇒ phantom-counts only its *own* stake, which gains nothing over signing honestly. Cannot cancel an honest `pk_H` (registering `-pk_H` needs a PoP over `"ALPENGLOW"||vote_account` the attacker can't forge; registering the same `pk_H` is dropped by rank-map dedup, `epoch_stakes.rs:119`).
3. **Byzantine threshold unchanged** ⇒ no cert accepted below its true threshold of genuine endorsers; the double-notarization/conflicting-cert path still needs ≥Byzantine-bound overlap.
- Residual: 🟡 SPECULATIVE **slashing-accountability** nuance — cancellation lets a coalition be *counted* as endorsers without leaving a verifiable individual signature; if any slashing logic relies on signature evidence rather than bitmap membership, it could be weakened. Out of the audited files; flagged for the votor/slashing owner. NOT a threshold break on its own.
- Actionable hardening (not a bounty submission): add `is_identity()` to `try_build_base2_cert` to match #14390.
## Area 5 — Reward certs & validator admission  (agent: rewards) — RETURNED — SOLID (high confidence)
- ✅ **No unearned credit.** Replay path uses `ValidatedRewardCert::try_new` (not the leader's trusting `try_new_for_leader`); the credited `validators` set is populated only as a side effect of the rank-map closure inside `verify_base2`, so a bit set for a non-signer makes the aggregate signature mismatch and the whole cert rejects. Credited pubkey and stake both come from the same `epoch_stakes_from_slot(reward_slot)`.
- ✅ **No double credit.** `extract_slot` requires `reward_slot + NUM_SLOTS_FOR_REWARD(8) == current_slot` → a reward cert for slot R is only valid in the block at R+8; one rooted block per slot ⇒ credited once. Finalize-cert path pays zero lamports. Combined path visits each validator once (`union`).
- ✅ **Arithmetic conserves.** `reward = max_validator_reward * stake_i / (slots_per_epoch * total_stake)` in u128, telescopes to exactly `max_validator_reward`/epoch; no attacker-controlled input; every failure mode errs toward under-payment.
- ✅ **Strongest lead ruled out: rank-map dedup eviction.** `epoch_stakes.rs:111-123` drops both copies of a duplicated BLS/node pubkey (could shrink total_stake / evict a victim) — but registering a BLS pubkey needs a PoP signed over `"ALPENGLOW" || vote_account_pubkey` (`programs/vote/src/vote_state/mod.rs`), so an attacker can't forge a victim's key or reuse a captured PoP. Node-pubkey collision blocked by `verify_authorized_signer`. Closed.
- ✅ Rank map deterministic (sort by stake desc, bls-pubkey asc — unique tiebreak); reward-cert bitmap parsing bounded (≤64 KiB, `decode` rejects OOB ranks); single shared parser (no dual-parser divergence); VAT burn is self-inflicted (own admission ticket to incinerator), no cross-account theft.
- ❗ Two load-bearing claims a PoC *could* confirm-as-safe (not bugs): (a) honest replayers reject a leader block whose `try_new_for_leader` set disagrees with its emitted bitmap (bank-hash mismatch); (b) PoP binding prevents duplicate-BLS registration end-to-end. Both verified by source + in-tree adversarial tests.
